# Орбита

Многопользовательский космический симулятор для WebXR (Quest и другие VR-шлемы) и ПК.
Сервер — FastAPI: отдаёт статическую игру из `app/static` и держит WebSocket `/ws` для мультиплеера.

## Быстрый старт: всё в Docker

`docker/game/docker-compose.yml` запускает все сервисы разом:

| Сервис | Что делает |
|---|---|
| `nginx` | HTTPS на порту 8080 (`docker/nginx/nginx.conf`): WebSocket `/ws?map=<id>` отправляет в шард этой карты (id карты начинается с имени шарда), остальное — в `web` |
| `web` | сервер игры без карт: файлы игры, `/ice` и `/api/maps` (список карт собирает с шардов, новую карту создаёт на наименее загруженном) |
| `map-alpha`, `map-beta`, `map-gamma` | шарды: серверы игры, на которых живут карты игроков (`ORBITA_SHARD`), — у каждого шарда своё ядро процессора |
| `coturn` | TURN-сервер для голосового чата (сеть хоста, порты 3478, 5349, 49160–49200) |
| `certbot`, `cert-copy` | выпуск/продление сертификата и копирование его в `shadow/` — запускаются вручную (профиль `cert`) |

Перед первым запуском в `shadow/` должны лежать сертификат (`fullchain.pem`, `privkey.pem`, см.
«Сертификаты») и `shadow/turn.env` (см. «TURN-сервер»). Все команды `docker compose` в этом README
выполняются из `docker/game`:

```bash
cd docker/game
docker compose up -d --build      # собрать и запустить всё вместе с coturn (перезапускаются сами)
docker compose ps                 # состояние
docker compose logs -f map-alpha  # логи одного шарда (или nginx, web, coturn; без имени — всех)
docker compose restart            # перезапуск, например после обновления сертификата
docker compose down               # остановить всё
```

После изменений в коде сервера или игры (`app/`) пересоберите образ: `docker compose up -d --build`.
Контейнеры игры и coturn работают от пользователя с uid/gid 1000 — владельца `shadow/` (coturn читает
приватный ключ); если у вас другой, задайте `HOST_UID` и `HOST_GID` (например, в файле `docker/game/.env`).
Новый шард — это имя в `ORBITA_SHARDS` сервиса `web`, сервис `map-<имя>` в `docker-compose.yml` и маршрут
в `docker/nginx/nginx.conf`.
Образ собирается из корня проекта, но в него попадают только `app/` и `requirements.txt`
(`docker/game/Dockerfile.dockerignore`).

## VDS

На главный сервер, выкладывается скриптом с локальной машины. Адрес сервера — в `shadow/deploy.env`
(`DEPLOY_HOST=root@<ip>`, необязательно `DEPLOY_DIR`), домен — `TURN_HOST` из `shadow/vds/turn.env`:

```bash
scripts/deploy.sh --with-shadow   # первый раз и после смены секретов
scripts/deploy.sh                 # дальше: собрать образ, загрузить, перезапустить игру
```

Скрипт собирает образ локально, переносит его по ssh, кладёт `docker/` в `/srv/orbita` и запускает compose с
`docker/game/vds.env`: порты 443 и 80 напрямую (роутера нет), PostgreSQL — сервис `db` (профиль `db`, наружу
не открыт). Секреты VDS лежат в `shadow/vds/` (`turn.env`, `auth.env`, `db.env`) и копируются в
`/srv/orbita/shadow/` с флагом `--with-shadow`. Сертификат выпускается на самом VDS при первом деплое,
продлевает его еженедельное задание `/etc/cron.d/orbita-cert`.

### Безопасность VDS

Настроено вручную, `scripts/deploy.sh` этого не делает.

**Файрвол.** Правила хоста — `docker/host/firewall.sh` (на сервере `/usr/local/sbin/firewall.sh`), включаются при
загрузке юнитом `docker/host/firewall.service` (`/etc/systemd/system/firewall.service`). Скрипт трогает только
цепочку `INPUT`, цепочки Docker не меняет. Политика `DROP` для IPv4 и IPv6, открыто:

| Порт | Зачем |
|---|---|
| 22/tcp | SSH, не больше 10 новых подключений в минуту с одного IP |
| 443/tcp | nginx |
| 3478, 5349 tcp+udp | coturn |
| 49160–49200/udp | ретрансляция coturn (`min-port`..`max-port` в `turnserver.conf`) |

Плюс ICMP/ICMPv6, DHCP и трафик из контейнеров к хосту. Порты, опубликованные Docker'ом (443, 80 у certbot),
по IPv4 идут через DNAT и цепочку `FORWARD`, а не через `INPUT`, поэтому продление сертификата файрвол не
ломает. Ограничивать опубликованные порты — в цепочке `DOCKER-USER`, не в `INPUT`.

Юниту нужен `DefaultDependencies=no`: без него он ждёт `sysinit.target`, который держит cloud-init до
появления сети, а сеть ждёт файрвол — система загружается без сети (см. `REPORT.txt`).

Поменять правила:

```bash
scp docker/host/firewall.sh <host>:/usr/local/sbin/firewall.sh
# страховка: если доступ пропадёт, через 5 минут файрвол откроется сам
ssh <host> 'echo "iptables -P INPUT ACCEPT; ip6tables -P INPUT ACCEPT; iptables -F INPUT; ip6tables -F INPUT" | at now + 5 min'
ssh <host> systemctl restart firewall
# проверить из НОВОГО подключения: ssh, сайт, голос; затем отменить откат
ssh <host> 'atrm $(atq | cut -f1)'
```

**SSH** — `/etc/ssh/sshd_config.d/10-hardening.conf`: вход только по ключу (`PasswordAuthentication no`),
`X11Forwarding no`, `MaxAuthTries 3`.

**fail2ban** — `/etc/fail2ban/jail.d/sshd.local`: 5 неудачных входов за 10 минут — бан на час. Свои адреса —
в `ignoreip`. Баны живут в отдельной таблице nftables (`inet f2b-table`) и с `firewall.sh` не пересекаются.
Посмотреть: `fail2ban-client status sshd`.

**Прочее:**
- `/etc/sysctl.d/99-hardening.conf` — `send_redirects = 0`;
- nginx — `server_tokens off` (версия не видна в заголовке `Server`);
- coturn — ретрансляция в частные сети и на собственный IP сервера запрещена (`denied-peer-ip`);
- обновления безопасности ставит `unattended-upgrades`; ядро применяется только после перезагрузки
  (есть ли ожидающая — `ls /var/run/reboot-required`).

Перед перезагрузкой после изменений в загрузке (юниты, ядро, сеть) — держать открытой консоль хостера.
Если сервер не поднялся: Rescue-система хостера, `mount /dev/sda1 /mnt`, журнал прошлой загрузки —
`journalctl -D /mnt/var/log/journal -b -1`.

## Без Docker

Виртуальное окружение — сам корень проекта (Python 3.12):

```bash
python3.12 -m venv .
bin/pip install -r requirements.txt
```

### Локально, для разработки

```bash
bin/fastapi dev app/main.py --host 0.0.0.0 --port 8000
```

Игра откроется на http://localhost:8000. VR в браузере работает только по HTTPS или на `localhost`,
поэтому для шлема нужен запуск с сертификатом (ниже).

### В интернет, по HTTPS

На роутере проброшены порты:

| Внешний порт | Локальный порт | Для чего |
|---|---|---|
| 80 | 8000 | проверка домена при выдаче сертификата (certbot) |
| 443 | 8080 | игра по HTTPS |
| 3478 UDP и TCP | 3478 | TURN/STUN для голосового чата (coturn) |
| 5349 TCP | 5349 | TURN поверх TLS |
| 49160–49200 UDP | 49160–49200 | ретрансляция голоса через TURN |

В Docker это делает сервис `nginx` (`docker compose up -d`). Без Docker можно запустить один процесс со
всеми картами (шард `local`) — он займёт одно ядро процессора (Docker перед этим остановите, порт 8080 один):

```bash
bin/uvicorn app.main:app --host 0.0.0.0 --port 8080 \
  --ssl-certfile shadow/fullchain.pem --ssl-keyfile shadow/privkey.pem
```

## Сертификаты Let's Encrypt

Сертификат выпускает certbot в Docker (сервис `certbot` в `docker/game/docker-compose.yml`) в режиме standalone:
на время проверки он сам поднимает веб-сервер на локальном порту 8000, куда роутер пробрасывает внешний 80.
**Порт 8000 в этот момент должен быть свободен** — остановите `fastapi dev`, если он запущен.

Всё хранится в `shadow/` (папка в `.gitignore`, приватный ключ в git не попадёт):

- `shadow/etc-letsencrypt/` — рабочие файлы certbot (принадлежат root);
- `shadow/fullchain.pem`, `shadow/privkey.pem` (а также `cert.pem`, `chain.pem`) — копии, которые читает сервер игры.

### Выпустить сертификат

Из `docker/game`:

```bash
cd docker/game
# пробный прогон на тестовом сервере Let's Encrypt — не расходует лимиты
docker compose run --rm --service-ports certbot certonly --standalone -d [domein_name] \
  --non-interactive --agree-tos --register-unsafely-without-email --dry-run
# настоящий выпуск
docker compose run --rm --service-ports certbot certonly --standalone -d [domein_name] \
  --non-interactive --agree-tos --register-unsafely-without-email
# копия в shadow/ для сервера игры и coturn
docker compose run --rm cert-copy
```

### Обновить сертификат

Сертификат действует 90 дней (текущий — до 6 января 2027). Certbot продлевает его, если до окончания
осталось меньше 30 дней; раньше команда ничего не делает.

```bash
cd docker/game
docker compose run --rm --service-ports certbot renew
docker compose run --rm cert-copy
docker compose restart            # nginx и coturn читают сертификат только при старте
```

### Скопировать сертификат для сервера

Файлы в `shadow/etc-letsencrypt/live/` — символические ссылки внутри папок root, поэтому их копирует
контейнер `cert-copy`: кладёт `fullchain.pem`, `privkey.pem`, `cert.pem`, `chain.pem` в `shadow/` и отдаёт
их пользователю `HOST_UID:HOST_GID` (по умолчанию 1000:1000), ключ — с правами 600:

```bash
docker compose run --rm cert-copy
```

Проверить срок действия:

```bash
openssl x509 -in shadow/fullchain.pem -noout -subject -dates
```

### Если проверка не проходит

`Timeout during connect` значит, что Let's Encrypt не достучался до порта 80. Проверьте:

- `dig +short [domein_name]` совпадает с внешним IP (`curl -4 ifconfig.me`);
- на роутере правило 80 → 8000 указывает на эту машину и включено;
- порт 8000 свободен: `ss -ltn | grep :8000`.

Снаружи порт можно проверить через https://check-host.net (TCP-проверка `[domein_name]:80`), пока на 8000
что-нибудь слушает, например `python3 -m http.server 8000`.

## Аккаунты: регистрация и вход

Страница `/login.html` (ссылка «Вход / регистрация» в меню игры): вход через Google, Apple, Discord,
Meta или по e-mail с паролем. Для e-mail нужна капча (Cloudflare Turnstile) и подтверждение адреса
письмом: войти с паролем можно, только открыв ссылку из письма. Забытый пароль восстанавливается по
почте: «Забыли пароль?» → e-mail и капча → письмо со ссылкой (действует час) → новый пароль; после этого
все остальные сессии пилота закрываются, а адрес считается подтверждённым. На неизвестный адрес ответ
тот же, письма одного вида уходят не чаще раза в минуту. Играть могут только вошедшие пилоты (см. «Только для зарегистрированных»). Сервер — `app/auth.py` (e-mail, сессии, капча), `app/oauth.py`
(провайдеры), `app/mail.py` (письма); страница — `app/static/login.html` и `app/static/js/auth.js`.

Настройки лежат в `shadow/auth.env` (в git не попадает, права 600); переменные окружения важнее файла:

| Переменная | Значение |
|---|---|
| `DATABASE_URL` | `postgresql://postgres:<пароль>@localhost:5432/orbita`; без неё аккаунты выключены |
| `PUBLIC_URL` | адрес сайта для ссылок в письмах и OAuth: `http://localhost:8000` или `https://[domein_name]` |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`, `SMTP_FROM` | почта; без `SMTP_HOST` ссылка из письма пишется в лог сервера |
| `TURNSTILE_SITE_KEY`, `TURNSTILE_SECRET` | ключи капчи; в файле стоят тестовые ключи Cloudflare, которые пропускают всех |
| `GOOGLE_CLIENT_ID`/`_SECRET`, `DISCORD_CLIENT_ID`/`_SECRET`, `META_CLIENT_ID`/`_SECRET` | ключи OAuth-приложений |
| `APPLE_CLIENT_ID` (Services ID), `APPLE_TEAM_ID`, `APPLE_KEY_ID`, `APPLE_PRIVATE_KEY_FILE` | Sign in with Apple; ключ `.p8` — путь от корня проекта, например `shadow/apple.p8` |
| `METRICS_TOKEN` | токен для `/metrics` (см. «Метрики»); без него эндпоинта нет |

Кнопка провайдера работает, когда заданы его ключи (иначе она серая). В настройках каждого приложения
у провайдера укажите адрес возврата `<PUBLIC_URL>/auth/<provider>/callback`, где `<provider>` —
`google`, `apple`, `discord` или `meta`. Где взять ключи: Google Cloud Console → APIs & Services →
Credentials (OAuth client, Web application); Discord Developer Portal → OAuth2; Meta for Developers →
приложение с Facebook Login; Apple Developer → Identifiers (Services ID с Sign in with Apple) и Keys.
Apple принимает только HTTPS-адреса.

### Ник в мультиплеере

Имя аккаунта — это ник пилота в игре, и оно уникально без учёта регистра. Сервер карты при подключении
к `/ws` смотрит cookie сессии: вошедший пилот летает только под именем своего аккаунта, что бы ни прислал
браузер (в меню поле имени заблокировано). Гости (только там, где они разрешены, см. ниже) выбирают
имя сами, но с именем, которое принадлежит аккаунту, гость летает как `Pilot-<номер>`; имена вида
`Pilot-<число>` оставлены гостям и для аккаунтов недоступны. Имя меняется в профиле (`/profile.html`) и действует со следующего
входа на карту. При регистрации занятое имя не принять, при входе через провайдера к занятому
имени добавляется номер (`Maverick2`). Неподтверждённые регистрации старше двух дней удаляются при
следующей регистрации и освобождают имена.

Один аккаунт — один корабль: когда пилот входит в игру с аккаунта, который уже в игре (другая вкладка,
другое устройство или другая карта), старое подключение закрывается с кодом 4001. Эта вкладка не
переподключается сама, а возвращается в меню с объяснением; если начать игру в ней снова, закроется уже
другое подключение. Процессы карт сообщают друг другу о новом входе через PostgreSQL (`LISTEN/NOTIFY`,
канал `orbita_kick`).

Поэтому базу используют и контейнеры карт.

### Профиль пилота

`/profile.html?id=<id>` (или `?name=<имя>`) — страница пилота, открытая всем, без входа: аватар, имя,
дата регистрации и статистика. Без параметров открывается свой профиль (в меню игры — ссылка «Аккаунт»).
Владелец меняет на ней аватар и ник. Сервер — `app/profile.py`, страница — `app/static/profile.html` и
`app/static/js/profile.js`; e-mail в публичный профиль не попадает.

`<id>` в ссылках на профиль и аватар — публичный случайный UUID пилота (`users.public_id`, миграция 0007), а не
номер аккаунта: перебором номеров пилотов не перечислить, и число аккаунтов не видно. Вдобавок nginx
ограничивает частоту запросов с одного адреса: `/api/profile` и `/api/leaders` — 5 в секунду (с запасом 20),
`/avatar/` — 20 в секунду (с запасом 120: таблица лидеров грузит до сотни аватаров разом); сверх лимита — 429.

Статистику считает сервер карты (`app/stats.py`) по тому, что видит сам, поэтому подделать её из браузера
нельзя:

| Показатель | Как считается |
|---|---|
| Опыт | сбитый пилот +250, пират +100, астероид +10 |
| Часы налёта | время, пока корабль в космосе: жив, в игре, не на стыковке |
| Победы (сбито кораблей) | пилоты и пираты вместе |
| Поражения | гибели корабля (от чего угодно) |

Сбитый пилот засчитывается, только если победитель попадал в него за последние 10 секунд, — «подарить»
победу, нарочно разбившись, не выйдет. Процесс карты копит изменения в памяти и добавляет их в
`player_stats` раз в 30 секунд и при остановке; пока база недоступна, они ждут следующей записи.

Аватар браузер обрезает до квадрата 256×256 и пересохраняет в JPEG (метаданные фото при этом пропадают);
сервер принимает только PNG, JPEG или WebP (проверяет по содержимому файла) до 256 КБ и хранит их в
таблице `avatars`, отдаёт по `/avatar/<public_id>`.

### Таблицы лидеров

`/leaders.html` — 100 лучших пилотов по опыту, `/leaders.html?by=flight` — по часам налёта,
`/leaders.html?by=wins` — по победам, то есть сбитым пилотам и пиратам вместе (вкладки на странице); открыты всем, ссылки — в меню игры и в профиле. В таблице место, аватар и ник (ведёт в
профиль), опыт, налёт (часы и минуты), сбитые корабли и поражения; на узком экране остаются место, пилот
и колонка открытой таблицы. При равенстве выше тот, кто зарегистрировался раньше; пилоты без опыта, налёта
или побед в соответствующую таблицу не попадают. Вошедший пилот видит свою строку подсвеченной, а если он не в первой сотне — своё
место отдельной строкой внизу. API — `GET /api/leaders?by=xp|flight|wins` (`app/profile.py`).

### Только для зарегистрированных

Когда аккаунты настроены (`DATABASE_URL`), играть могут только вошедшие пилоты. В меню без входа вместо
«Играть» стоит «Войти, чтобы играть» (ведёт на `/login.html` и после входа обратно в игру), кнопка VR
тоже сначала отправляет на вход. Сервер карты закрывает подключение без действующей сессии с кодом 4401;
если сессия кончилась или пилот вышел из аккаунта посреди игры, при следующем переподключении он
вернётся в меню с объяснением.

Если база недоступна, проверить сессию нельзя: подключения закрываются с кодом 4503, клиент пробует
снова, как после обрыва связи, а сервер переподключается к базе каждые 10 секунд. Без `DATABASE_URL`
(локально без базы) аккаунтов нет и играют все. `ALLOW_GUESTS=1` пускает гостей и при настроенных
аккаунтах — это для нагрузочного теста, на боевом сервере не включайте.

### База данных и миграции

Таблицы: `users` (пилоты), `identities` (привязанные аккаунты провайдеров), `email_tokens` (ссылки из
писем — подтверждение и сброс пароля, хранится только хэш), `sessions` (вошедшие браузеры, cookie `orbita_session`, 30 дней),
`oauth_states` (входы через провайдера, пока пилот на его странице), `player_stats` (статистика),
`avatars` (аватары), `schema_migrations`. Миграции —
SQL-файлы `app/migrations/NNNN_*.sql`; сервер при старте сам создаёт базу `orbita`, если её нет, и
применяет новые миграции. Вручную:

```bash
bin/python -m app.db
```

Новая миграция — следующий по номеру файл в `app/migrations`; уже применённые файлы не меняйте.

В Docker аккаунтами занимается контейнер `web`: он читает `shadow/auth.env` (папка `shadow/` подключена
к контейнерам игры только для чтения) и ходит в PostgreSQL на хосте через `host.docker.internal` (`DATABASE_HOST` в
`docker-compose.yml`). Контейнеры карт так же подключены к базе — для ников пилотов.

## Музыка и громкость

Фоновая музыка — случайные треки из папок `app/static/music/<папка>/` (mp3, ogg, m4a, opus, wav), один за
другим без повтора подряд (`app/static/js/music.js`); список отдаёт `GET /api/music`, новые файлы
подхватываются без перезапуска. Какая папка где играет:

| Где | Папка |
|---|---|
| вход и регистрация (`/login.html`) | `login` |
| меню игры (выбор карты), профиль, таблицы лидеров | `profile` |
| полёт | `battle` |

Смена папки (например, старт игры и выход в меню) плавно приглушает текущий трек. Браузер не играет звук,
пока на странице не было клика или нажатия клавиши, поэтому музыка начинается с первого действия, а до
него рядом с кнопкой ♪ в углу (на всех страницах, в игре — только в меню) висит подсказка «Нажмите в любом
месте, чтобы включить музыку».

Громкость настраивается в меню игры, блок «Громкость»: «Звуки» (звуки игры), «Музыка» и «Голоса»
(голосовой чат), от 0 до 100 % каждая; изменения слышны сразу, браузер их запоминает
(`app/static/js/volume.js`). Во время полёта те же ползунки открывает кнопка ⚙ (настройки) в правом верхнем углу
(на ПК и телефоне) или клавиша **M** — игра при этом не останавливается. В той же панели есть переключатели
«Голосовой чат» и «Инверсия вверх/вниз» — они действуют сразу и совпадают с теми, что в меню. В VR-шлеме страница не видна,
так что громкость там меняется только в меню до входа в VR. Музыка на 0 % — выключена; кнопка ♪ в углу выключает
музыку и возвращает прежнюю громкость. На iPhone браузер не даёт менять громкость музыки и голосов из страницы — там работает только
выключение музыки и громкость звуков игры.

## Телефоны и планшеты

На телефоне игра сама включает сенсорное управление (`app/static/js/touch.js`): плавающий стик под
левым пальцем — тангаж (вниз — нос вверх) и крен, ползунок справа — тяга (остаётся, где отпустили),
кнопки «Огонь» (держать), «Форсаж» (держать) и «Стоп», сверху — меню, сброс взгляда и микрофон;
свайп в центре экрана — оглядеться в кабине. Рыскания в сенсорной схеме нет — хватает тангажа и крена.

Сенсорный режим включается, если у устройства нет мыши (`(hover: none) and (pointer: coarse)`);
принудительно — `?touch=1` или `?touch=0` в адресе. В этом режиме экраны в кабине стоят ближе к центру
(не под кнопками), поле зрения подогнано под широкий экран, плотность пикселей ограничена 1,5, а
вибрация срабатывает на попадания и сбитые корабли. На Android игра уходит в полноэкранный режим и
фиксирует альбомную ориентацию; на iPhone Safari этого не умеет — в портретной ориентации игра просит
повернуть телефон.

## Джойстик

Кроме VR-контроллеров, клавиатуры и геймпадов игра понимает лётные джойстики (раскладка рассчитана на
Thrustmaster T.Flight HOTAS X): ручка — тангаж и крен, поворот ручки и качалка на РУДе — рыскание,
рычаг газа задаёт тягу, курок — лазеры, кнопки 2/3/4 — форсаж/стоп/сброс взгляда, 5 — микрофон.
Раскладка осей и кнопок — `JOY` и `JOY_BUTTONS` в `app/static/js/input.js`.

Браузер показывает джойстик странице только после нажатия любой его кнопки. В Ubuntu Firefox и
Chromium стоят из snap, и доступ к джойстику им надо выдать один раз:

```bash
sudo snap connect firefox:joystick    # или chromium:joystick
```

После этого браузер нужно перезапустить.

## Мультиплеер

Каждый клиент отправляет серверу положение своего корабля, сервер 20 раз в секунду рассылает
снимок остальных игроков и пересылает выстрелы, попадания и сбитые корабли. Попадание по игроку
определяет стреляющий клиент, сервер проверяет дистанцию и темп стрельбы.

В снимок попадают только корабли в радиусе 6 км от игрока (`INTEREST_RADIUS` в `app/room.py`); уже
видимый корабль пропадает дальше 7 км (`INTEREST_KEEP`), чтобы не мигать на границе. Так же по
расстоянию отбираются чужие выстрелы и залпы пиратов, а пираты, зоны, сообщения о сбитых и
вошедших/вышедших пилотах идут всем на карте. Список всех пилотов карты (имя, включён ли голосовой
чат) сервер присылает отдельным сообщением `roster`, когда он меняется: по нему работают голосовой чат
и счётчик онлайна.

### Карты

Изначально на сервере карт нет — их создают игроки. В меню пилот выбирает тип карты, и в списке
появляются до 10 открытых карт этого типа (самые населённые первыми, с числом пилотов «5/40»);
можно войти в любую или выбрать «+ Новая карта». Пустые и заполненные карты в списке не показываются;
карта, на которой 60 секунд никого нет, закрывается (`EMPTY_TTL` в `app/main.py`). Новую карту можно
сделать закрытой: в списке её нет, войти можно только по ссылке `/?map=<id>` — её показывает меню
(Esc) с кнопкой «Копировать». Сервер: `GET /api/maps?type=<тип>` (список), `GET /api/maps/<id>` (карта
по ссылке), `POST /api/maps` (создать: только вошедшим пилотам, если гостей не пускают); игра
подключается к `/ws?map=<id>`.

| Тип | Пилотов | Что на карте | Информационное окно |
|---|---|---|---|
| Farming space (`farm`) | 1–40 | пираты в нескольких зонах, астероиды, три станции для ремонта; пилоты друг в друга не стреляют | очки и победы за всё время |
| PvP (`pvp`) | 1–40 | только пилоты и три станции; все стреляют во всех | очки и победы на этой карте |
| Team battle (`team`) | 2–20 | две команды по 1–10, у каждой своя база; чиниться можно только на своей | время раунда (или отсчёт), очки команд, свои очки и победы за раунд |
| Save station (`station`) | 2–20 | как Team battle, но базы можно разрушить | то же и состояние баз: прочность и сколько раз разрушена |

Правила типов — в `app/modes.py`, базы — в `app/game.py`, раунды — в `app/room.py`. Очки: сбитый
пилот +250 (и победа), пират +100 (и победа), астероид +10, разрушенная база +1000.

**Командные карты.** Новый пилот попадает в команду, где меньше игроков (синие или красные — по цвету
кольца базы и контура кораблей), и появляется у своей базы. Раунд начинается, когда «Готов» нажали все
пилоты на карте и в каждой команде есть хотя бы один: 10 секунд отсчёта, затем 20 минут боя, все
стартуют от своих баз. Между раундами оружие не работает и можно сменить команду (если в ней меньше
10 пилотов). Побеждает команда, набравшая больше очков (огня по своим нет). В Save station у базы
1800 единиц прочности (около 300 попаданий); база, по которой 10 секунд не стреляли, сама чинится, а
разрушенная через 30 секунд появляется снова — до тех пор у её команды нет ремонта. Команда, чью базу
разрушили 3 раза за раунд, сразу проигрывает. «Готов» — кнопка под информационным окном или клавиша
**G** (Y на левом VR-контроллере, A на геймпаде), сменить команду — кнопка, **T** (нажатие левого
стика в VR, Back на геймпаде).

**Информационное окно** вверху по центру (`app/static/js/info.js`) на экране — поверх страницы, в VR —
голограммой в верхней части фонаря кабины.

**Шарды.** В Docker карты живут на нескольких процессах-шардах (`map-alpha`, `map-beta`, `map-gamma`).
id карты начинается с имени шарда (`alpha-3f9c…`), по нему nginx отправляет `/ws` нужному процессу;
`web` спрашивает у шардов их карты через `/internal/maps` (снаружи nginx этот путь не пускает) и
создаёт новую карту на шарде, где меньше всего пилотов и карт. Без переменных `ORBITA_SHARD` /
`ORBITA_SHARDS` один процесс делает всё сам.

Пираты и астероиды общие для всех пилотов одной карты, у каждой карты свои: сервер (`app/game.py`)
ведёт пиратские зоны и поведение пиратов —
каждый пират атакует ближайшего игрока в досягаемости своей зоны, — считает урон пиратам и астероидам
и рассылает их выстрелы. Игроки могут вместе бить одного пирата; очки за уничтоженного пирата
(+100) и астероид (+10) получает тот, чей выстрел был последним. Зоны генерируются заново для каждой
новой карты.

### Голосовой чат

Пилоты одной карты могут говорить друг с другом: звук идёт напрямую между браузерами по WebRTC
(`app/static/js/voice.js`), сервер только пересылает сообщения для установки соединения (`rtc`).
Галочка «Голосовой чат» в меню включает чат — браузер спросит доступ к микрофону; микрофон сначала
выключен, включается и выключается клавишей **V** (B на правом VR-контроллере или геймпаде).
На сканере имя говорящего пилота показано в скобках: `[Имя]`, на правом экране — состояние микрофона.

Микрофон в браузере доступен только по HTTPS или на `localhost`. Если браузеры не могут соединиться
напрямую (строгий NAT, мобильные или корпоративные сети), голос идёт через наш TURN-сервер coturn.

### Нагрузочный тест

`test/load_test.py` подключает к `/ws` ботов, которые ведут себя как игроки: летают по кругу,
15 раз в секунду сообщают своё положение, а часть из них непрерывно стреляет. Ботов добавляют этапами
(`--bots 10,30,60`). После каждого этапа тест печатает, что получили боты, а с `--pid` — ещё нагрузку
на процессор и исходящий трафик серверного процесса (читает `/proc`, поэтому только Linux и только
на той же машине).

Сервер для теста лучше запустить через `uvicorn` без `--reload`, чтобы он был одним процессом (все
карты в нём). Перед стартом тест сам создаёт карты (`--create 3` карт типа `--type farm`) через
`POST /api/maps`. У ботов нет аккаунтов, поэтому серверу нужен `ALLOW_GUESTS=1` (или пустой `DATABASE_URL=`):

```bash
ALLOW_GUESTS=1 bin/uvicorn app.main:app --port 8000 --log-level warning &
bin/python test/load_test.py --url ws://localhost:8000/ws --bots 10,30,60,100,150 --pid $!
```

По умолчанию боты летают в пределах 3 км от станции и почти все видят друг друга. Чтобы проверить игроков,
разлетевшихся по карте (отбор ближайших кораблей тогда экономит трафик и процессор), задайте
`--spread 12000`. Худший случай — все рядом, на одной карте PvP, и все стреляют:

```bash
bin/python test/load_test.py --url ws://localhost:8000/ws --bots 20,40,60,80 --create 1 --type pvp --fire 1 --pid <PID>
```

Сервер в Docker проверяют через nginx: `--url wss://localhost:8080/ws --insecure` (`--insecure` — не
проверять сертификат) или `--url wss://[domein_name]/ws`. Осторожно: боты появятся
у живых игроков, если зайдут на их карты, а `web` и шардам на время теста нужен `ALLOW_GUESTS: "1"` в
`environment` (уберите его после теста). Карты боты создают сами, `web` раскладывает их по шардам. PID
процессов шардов для `--pid`:

```bash
PIDS=$(for m in alpha beta gamma; do docker top vr_orbita-map-$m-1 | awk 'NR==2{print $2}'; done | paste -sd,)
bin/python test/load_test.py --url wss://localhost:8080/ws --insecure --procs 6 --bots 150,300,450 --pid $PIDS
```

Один процесс Python с ботами сам упирается в процессор примерно на 150–200 ботах (особенно по TLS),
поэтому для больших тестов делите ботов между процессами: `--procs 6`. Если тест запущен на той же
машине, что и сервер, они делят процессор, и сервер в таких замерах выглядит слабее, чем в бою.

Параметры: `--create` и `--type` — сколько карт какого типа создать, `--maps` — вместо этого id уже
существующих карт через запятую (боты раскладываются по очереди), `--fire` — доля стреляющих
ботов (0..1), `--duration` — длительность замера одного этапа в секундах, `--warmup` — пауза после
добавления ботов, `--spread` — в каких пределах от станции (м) летают боты, `--procs` — на сколько
процессов разделить ботов, `--pid` — PID процессов сервера через запятую. Полный список: `bin/python test/load_test.py -h`.

| Колонка | Что значит |
|---|---|
| `snap/s` | снимков в секунду на бота; норма — 20 |
| `tick p50/p95/max` | интервал между снимками, мс; норма — 50 |
| `recv Mbit/s`, `msg/s` | что получили все боты вместе (без сжатия WebSocket) |
| `srv CPU` | процессор самого загруженного процесса сервера; 100 % — его ядро загружено полностью, дальше эта карта не масштабируется |
| `srv out Mbit/s` | сколько процессы сервера реально отправили в сокеты (после сжатия, до TLS) — сравните с аплоадом канала |
| `test CPU` | процессор самого загруженного процесса теста; если он близок к 100 %, упирается тест, а не сервер — добавьте `--procs` |

Признак перегрузки — `snap/s` заметно меньше 20 и рост `tick`. Боты WebRTC и голос не используют.

### Метрики (Prometheus)

`GET /metrics` — метрики в текстовом формате Prometheus, только с заголовком
`Authorization: Bearer <METRICS_TOKEN>` (токен — в `shadow/auth.env`, на VDS — `shadow/vds/auth.env`;
без токена ответ 401, без настройки — 404). Цифры пересчитываются раз в минуту (`app/metrics.py`), так что
чаще опрашивать незачем:

```yaml
scrape_configs:
  - job_name: orbita
    scheme: https
    scrape_interval: 60s
    authorization: {credentials: <METRICS_TOKEN>}
    static_configs: [{targets: [domein_name]}]
```

| Метрика | Что значит |
|---|---|
| `orbita_step_seconds_mean`, `_p95`, `_max`{shard} | длительность шага симуляции (все карты шарда) за последнюю минуту |
| `orbita_step_budget_seconds` | бюджет шага — `TICK`, 0,05 с |
| `orbita_fell_behind`{shard}, `orbita_fell_behind_total` | сколько раз цикл отстал от расписания больше чем на шаг: за минуту и с запуска |
| `orbita_maps`, `orbita_players`{shard} | карт и пилотов на шарде сейчас |
| `orbita_ws_sent_bytes_per_second`{shard}, `orbita_ws_sent_bytes_total` | отправлено в WebSocket: в среднем за минуту и с запуска (до сжатия и TLS) |
| `orbita_container_cpu_cores`, `orbita_container_cpu_seconds_total`{container} | процессор сервиса: ядер в среднем за минуту, секунд с запуска |
| `orbita_container_memory_bytes`, `orbita_container_memory_limit_bytes`{container} | память сервиса и её лимит (если задан) |
| `orbita_up`{shard} | 1 — шард ответил на последний сбор |

Шард считает свои цифры сам и отдаёт их `web` на `/internal/metrics` (снаружи закрыт nginx). Процессор и
память читаются из cgroup: каждый сервис в `docker-compose.yml` запущен в своём systemd-слайсе
(`cgroup_parent: orbita-<сервис>.slice`), а `web` видит дерево cgroup хоста (`/sys/fs/cgroup` → `/host/cgroup`).
Нужны cgroup v2 и драйвер cgroup `systemd` у Docker (`docker info | grep -i cgroup`), так и на домашнем
сервере, и на VDS. Новый сервис попадёт в метрики, если дать ему такой же `cgroup_parent`.

## TURN-сервер (coturn)

coturn — сервис `coturn` в `docker/game/docker-compose.yml`, настройки — `docker/turn/turnserver.conf`. Секреты и
адреса лежат в `shadow/turn.env` (в `.gitignore`, права 600); его читают и coturn, и сервер игры:

| Переменная | Значение |
|---|---|
| `TURN_SECRET` | общий секрет coturn и сервера игры |
| `TURN_EXTERNAL_IP` | `внешний IP/LAN-адрес машины` |
| `TURN_LOCAL_IP` | LAN-адрес машины: coturn слушает и ретранслирует только на нём (и на `127.0.0.1`) |
| `TURN_HOST` | имя, к которому подключаются браузеры (`[domein_name]`) |

```bash
cd docker/game
docker compose up -d coturn       # только coturn
docker compose logs -f coturn     # логи
```

Постоянных паролей нет: сервер игры по `GET /ice` выдаёт браузеру временный логин на 6 часов,
подписанный `TURN_SECRET` (схема TURN REST API, `app/turn.py`). Сервер игры читает `TURN_SECRET` и
`TURN_HOST` из переменных окружения или из `shadow/turn.env`; без них голос работает только через
публичный STUN Google. Ретрансляция в частные сети (LAN, localhost) запрещена в конфиге.

Для TLS (порт 5349) coturn использует тот же сертификат `shadow/fullchain.pem` и `shadow/privkey.pem`.

Новый секрет: замените `TURN_SECRET` в `shadow/turn.env`
(`python3 -c 'import secrets; print(secrets.token_urlsafe(32))'`), затем `docker compose up -d` — оба
сервиса пересоздадутся с новыми настройками. Если сменится внешний IP — обновите `TURN_EXTERNAL_IP` и
выполните то же самое.
